# テスト計画・結果報告書
**OCTO-TEST-003: Bronzeフラット形式出力と CreateEvent（リポジトリ作成）追加の実データ検証**

---

## 1. 目的・対象範囲

- **目的**: `project_event` によるフラット形式のJSONL出力が、実データで想定どおりに生成されることを確認する。`CreateEvent`（リポジトリ作成）追加による出力量の増分と、日付境界の時間帯で `event_date` がファイル名の日付とずれないかを確認する。
- **テスト対象**: `fetch_hourly_stream` + `extract_target_events` + `project_event` の連結動作（`octopulse.ingestion`）。
- **対象外**: GCSへの書き込み、BigQueryへのロードジョブ（Bronzeへの取り込みは未実装）、`repo_age_days` のSQL導出。
- **関連する要求・設計**: `DS-001` 第2.2節・第2.3節、`DD-001` F-ING-006、`ADR-002`、Issue #14。

## 2. テスト戦略・合格基準

- [x] 手動確認（一時スクリプトによる実データ集計）
- [x] 回帰テスト（`tests/` のユニットテストは別途CIで実行）

- **選択理由**: 出力量と日付境界の挙動は、実データでしか確認できない。
- **合格基準**:
  1. 出力JSONLの全行が、REQUIRED列を欠かさずBronzeのキー構成と一致する（スキップ件数が説明可能であること）。
  2. 全出力行で `event_date` がファイル名の日付と一致する。ずれる場合は件数を把握し、対応を決める。
  3. 1時間あたりの出力量が、無料枠の見積もり（`DS-001` 第3章）を超えない。
- **使用する証跡**: 一時スクリプトの標準出力（本書 第4章・第5章）。スクリプトはOSの一時ディレクトリで実行後に削除した（リポジトリには含めない）。

## 3. テスト環境・前提条件

- **環境**: Windows、Python 3.12。標準ライブラリのみ（追加パッケージなし）。
- **テストデータ**: GH Archive の `2024-01-03-0.json.gz`（日付の先頭時間）と `2024-01-03-23.json.gz`（日付の末尾時間）。公開データで、機密情報は含まない。
- **前提条件**: ネットワークから `https://data.gharchive.org/` へ接続できること。
- **実行方法**: 一時スクリプトで各時間を `fetch_hourly_stream` → `extract_target_events` → `project_event` に通し、出力JSONLのバイト数（UTF-8）と件数を集計した。

### 表5-1: 出力件数・バイト数・CreateEvent・スキップ

| 時間 (UTC)        | 出力件数 | JSONLバイト数 | CreateEvent を除いた場合 | CreateEvent（repository）件数 | スキップ件数 |
| :---------------- | -------: | ------------: | -----------------------: | ----------------------------: | -----------: |
| `2024-01-03-0`    |   22,914 |     5,735,851 |                4,655,552 |                         4,083 |            0 |
| `2024-01-03-23`   |   22,475 |     5,597,091 |                4,552,474 |                         3,961 |            0 |

- **CreateEvent追加の増分**: `2024-01-03-0` で +1,080,299 bytes（約+23.2%）、`2024-01-03-23` で +1,044,617 bytes（約+22.9%）。1時間あたり約1.0〜1.1MB。
- **従来との比較**: 従来のネスト形式（4種のみ）は約6.2MB/時間（`2024-01-01-15`、23,911件。別の時間のため厳密な比較ではない）。フラット化（`actor.id`・`public` の削除）で縮小し、`CreateEvent` を加えても従来より小さい。
- **1日換算**: 約5.67MB × 24時間 ≒ 約135MB/日。GCSの7日保持は約1GB。
- **イベント種別の内訳**: `2024-01-03-0` は PullRequestEvent 9,513 / WatchEvent 5,897 / CreateEvent 4,083 / IssuesEvent 2,198 / ForkEvent 1,223。`2024-01-03-23` は PullRequestEvent 8,735 / WatchEvent 5,672 / CreateEvent 3,961 / IssuesEvent 2,745 / ForkEvent 1,362。

### 表5-2: event_date とファイル名日付の一致

| 時間 (UTC)      | 出力件数 | `event_date` 不一致 | 備考                                                         |
| :-------------- | -------: | ------------------: | :----------------------------------------------------------- |
| `2024-01-03-0`  |   22,914 |                   0 | 日付の先頭時間。全行が `2024-01-03`                          |
| `2024-01-03-23` |   22,475 |                   0 | 日付の末尾時間。全行が `2024-01-03`（翌日にずれるイベントなし） |

- **総合判定**: 合格
- **判定理由**: 合格基準1〜3をすべて満たした。GH Archive は `created_at`（UTC）の時間でファイルを分割しているため、`event_date`（`created_at` の日付部分）はファイル名の日付と一致する。
