## 1. 目的・対象範囲

- **目的**:
  - `DD-001` で規定された「インフライトストリーミング解凍」および「ゼロディスクI/O」が実データ（GH Archive実ファイル約83MB）で正常稼働することを実証する。
  - メモリ消費量が非機能目標（512MB以下）を大幅に下回ることを確認する。
  - 抽出された実イベントの分布・比率を確認し、CHAOSSモデリング（Issue #6: 足切りライン・重み付け）の客観的根拠を得る。

  - `src/octopulse/ingestion/stream_engine.py`
  - `scripts/verify_ingestion_stream.py`
- **対象データ**:
  - GH Archive 実アーカイブ: `2024-01-01-15.json.gz`（実圧縮サイズ 約83.1MB）

## 4. Issue #6（CHAOSSモデリング壁打ち）への示唆・提言

実データの計測結果から、以下の極めて重要な知見が得られた：

1. **足切りライン（母集団）の妥当性**:
   - 1時間でStarがついたリポジトリは約2,000件程度だが、その大半は「+1 star」の散発的イベント。
   - 当初仮案の「WatchEvent >= 3 かつ (Fork+Issue+PR) >= 1」を日次（24時間累計）に適用すると、ノイズリポジトリが90%以上カットされ、有意義な約1,000〜3,000件の上位アクティブ群に絞り込めることが確認できた。
2. **スパム・ボット検知フラグの必須性**:
   - PR上位に現れた `mergifyio-testing` のように、CI/CDテストボットによる大量PRのみで構成されるリポジトリが実際に存在する。
   - Silver/Gold層における異常値フラグ（StarとEngagementの乖離度）の導入は、分析精度担保のために不可欠であることが実証された。
3. **Engagement Depth の加重設計**:
   - PR数はFork数の約7倍発生しているため、単純合算ではなく、イベントごとの発生頻度を考慮した加重比率（例: `Fork * 2 + Issue * 1 + PR * 1`、または各指標の個別パーセンタイル合算）が望ましい。

## 5. 追補: 出力サイズの実測（2026-11-02）

初版では出力（GCSへ書き込むJSONL）のサイズを測定していなかった。同じ `2024-01-01-15.json.gz` で再測定した結果を記録する。件数（23,911件）と種別内訳は初版と一致した。

| 条件                     | 出力サイズ（1時間） | 1日換算（×24） | 備考                                                                               |
| :----------------------- | :-----------------: | :------------: | :--------------------------------------------------------------------------------- |
| 生イベントをそのまま出力 |    **312.1 MB**     |    約7.5 GB    | 無料枠（GCS 5GB / BigQuery 10GB）を超過。NFR-001を満たせない                       |
| `project_event` で射影   |     **6.2 MB**      |    約150 MB    | 実装（`gcs_uploader.py`）で採用。件数は同じ 23,911 件、重複IDなし、処理時間 4.7 秒 |

- 生出力の内訳: `PullRequestEvent` 286.3MB（約92%、1件あたり約23KB）、`IssuesEvent` 11.2MB、`ForkEvent` 10.7MB、`WatchEvent` 3.9MB。
- 原因: `PullRequestEvent` の `payload.pull_request` が巨大。射影は `DS-001` 第2.2節に従う。
- 制約: 1日換算は元日の1時間を24倍した単純換算であり、平日や時間帯による変動は未検証。複数日の実測は [Issue #14](https://github.com/xzyozi/gh-archive-lakehouse/issues/14) のBronzeロード時に行う。
- 母集団件数に関する補足: 同じ1時間で `WatchEvent >= 3` のリポジトリは221件（Star対象5,760件中）。第4章の「日次で約1,000〜3,000件」は推定だった。複数日の実測では約4,300〜6,200件で、推定は過小だった（[`TEST-002`](./TEST-002_CHAOSSモデリング閾値の実データ検証報告書.md)）。
