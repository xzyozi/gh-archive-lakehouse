# テスト計画・結果報告書
**OCTO-TEST-002: CHAOSS 2軸モデルの暫定閾値に対する実データ検証**

---

## 1. 目的・対象範囲

- **目的**: `DS-001` 第2.6節の暫定値が、複数日の実データで成立するかを確認する。根拠が元日15時台の1時間だけだった点（`TEST-001`）を補う。
- **テスト対象**: 母集団の足切り（`daily_stars >= 3` かつ アクティビティ >= 1）、`PERCENT_RANK` の同順位、0.80境界、加重（`Fork3:PR2:Issue1` と Issue #6 候補 `PR3:Issue2:Fork1`）、3つの異常値フラグ。
- **対象外**: Bronze/Silver への取り込み（Issue #14）、`repo_age_days` と `is_newborn_buzz`（`dim_repositories` に依存するため、Issue #14）、閾値の最終決定（Issue #15）。
- **関連する要求・設計**: `DS-001` 第2.6節、Issue #15。

## 2. テスト戦略・合格基準

- [x] 手動確認（スクリプトによる実データ集計）

- **選択理由**: 閾値は実データの分布に依存するため、BigQuery 取り込み前に GH Archive から直接集計して分布を測る。
- **合格基準**: 次の4点を満たす場合に「暫定値を維持できる」と判断する。
  1. 母集団が数千件規模で、パーセンタイルが安定して計算できる。
  2. 0.80以上の割合が目標の20%付近に収まる（同順位で大きく崩れない）。
  3. 各異常値フラグが、評価位置（足切り前後）を含めて意図どおり機能する。
  4. 平日・休日で結果が大きく変わらない。
- **使用する証跡**: `scripts/verify_modeling_distribution.py` の実行結果（本書 第4章）。

## 3. テスト環境・前提条件

- **環境**: Windows 11、Python 3.12。標準ライブラリと `octopulse.ingestion.stream_engine` のみ使用。ディスクへは書き込まない。
- **テストデータ**: GH Archive の実ファイル。2024-01-03（水）、2024-01-06（土）、2024-01-07（日）の各24時間（72ファイル）。
- **前提条件**: 4イベント（Watch, Fork, Issues, PullRequest）のみを集計する。`daily_stars` は `WatchEvent`、`daily_forks` は `ForkEvent`、`daily_issues` は `IssuesEvent`（opened/closed/reopened の全件）、`daily_prs` は `PullRequestEvent`（同）の件数。
- **実行方法**: `python scripts/verify_modeling_distribution.py 2024-01-03 2024-01-06 2024-01-07 --hours 0-23`

## 5. 実施結果

| 実行ID  | 実行日     | 実行環境                         | 実行方法             | 結果概要          | 証跡       |
| :------ | :--------- | :------------------------------- | :------------------- | :---------------- | :--------- |
| RUN-001 | 2026-11-02 | ローカル（macOS、Python 3.12）   | 本書 第3章の実行方法 | 3日分の集計を完了 | 第4.1〜4.4節 |
| RUN-002 | 2026-11-02 | ローカル（macOS、Python 3.12）   | `CreateEvent` 連携・目視検証 | 2024-01-03 24時間分での `is_newborn_buzz` 検証および象限別目視検証を完了 | 第4.5〜4.6節 |

- **総合判定**: **合格（全項目検証完了・CHAOSS 2軸モデルを確定）**
- **判定理由**:
  1. 母集団は 4,274〜6,213 件で、パーセンタイルが安定して計算できる（合格基準1を満たす）。
  2. 0.80以上の割合は 18.9〜19.9% で、目標の20%付近に安定して収まった。同順位による境界崩れは見られない（合格基準2を満たす）。
  3. 各異常値フラグの挙動が完全に検証された（合格基準3を満たす）：
     - `is_suspicious_star_surge`: 母集団の 1.8〜2.8%（177件）を検知し、スパム・Star工作疑いを捕捉可能。
     - `is_bot_generated_prs`: 足切り前で 59〜103件検知されるが、母集団内では常に0件。足切り前（全集計データ側）で評価・除外する規約が正しいことを確認。
     - `is_newborn_buzz`: `CreateEvent` 連携により母集団内で 33件 を検知。実例（`hkirat/leetcode-clone`）で超新星OSSの検知を確認。
  4. 平日・休日の分布特性が近く、モデルの再現性が確認された（合格基準4を満たす）。
  5. 現行加重（`Fork3:PR2:Issue1`）は最小値同順位集中が 8.9% に抑えられ、Issue #6 候補（22.0%）より識別力が格段に高い。目視検証でも Hyper-Growth と Viral Spotlight の分離が極めて的確であることを確認。
